# Bulk Catalogue Manager for WooCommerce — agent entry point

Read in this order, then start work: `docs/SPEC.md` (the agreed shared understanding; change it there before changing code), `docs/TICKETS.md` (80 tickets in build order; each ends with tests green), `docs/prototype/index.html` (open in a browser; it is the design the code must match), `docs/SCOPE-2026-09-21.md` (the owner's scoping answers).

## Hard rules from the owner (Wade Beckett)
- Standalone: works on a bare WordPress + WooCommerce site with nothing else installed and zero site-specific code. Edits native WooCommerce product data only, through WooCommerce CRUD classes.
- No dependency on, module for, detection of, or mention of any third-party plugin in code, docs or UI. Per-customer or per-group product access is out of scope permanently. No client names or client fields anywhere.
- Always free, GPL-3.0-or-later, built to WordPress.org directory standards from the first commit (WPCS, translation-ready, no external calls, uninstall cleanup, Plugin Check clean).
- "Beautiful" means simple and easy for a non-technical shop owner. Plain-English labels; never show a raw meta key.
- Variations are first-class. Every bulk write is previewed first, journaled, and reversible.
- Do not ask the owner to define these further. Fix it, do not ask.

## Identifiers (must match SPEC §15)
Slug and text domain `bulk-catalogue-manager-for-woocommerce`; prefixes `bcm_` / `BCM_` / `bcm-`; PHP namespace `BulkCatalogueManager`; REST namespace `bcm/v1`; PHP >= 8.1, WordPress >= 7.0, WooCommerce >= 10.0. UI on `@wordpress/dataviews` bundled via wp-scripts, server-side paged.

REST (T13): every `bcm/v1` route goes through `Rest\Routes::add()` from a `Rest\Controller` listed in `Routes::plugin()` — never call `register_rest_route()` directly (a test scans for it); `add()` skips, with `_doing_it_wrong()`, any route whose endpoints lack a callable, non-`__return_true` permission callback. Permission callbacks live in `Rest\Access`: `can_read` (`manage_woocommerce`, or `manage_options` under administrators only, filtered by `bcm_capability`), `can_write` (plus `edit_products`), `can_manage_terms` (plus `manage_product_terms`), `can_manage_settings` (`manage_options`), and per object `can_edit_object()` / `user_can_edit_object()` (`bcm_cannot_edit`). Build every refusal through `Rest\Refusal` (`create`, `forbidden`, `invalid`): a `bcm_` code, a §4.8 sentence and `data.status` — a test scans for any other `new WP_Error`. `Routes::client_settings()` gives T8 the namespace root and the `wp_rest` nonce. A change to the `/fields` payload must update `tests/Unit/Fields/fields.snapshot.json` deliberately. The wp-env checks for T5 (uninstall), T6 (tables and indexes after activation, idempotent reactivation, a version bump keeping rows) and T13 (anonymous 401, subscriber 403, shop manager 200, the administrators-only flip, a stale nonce 403 `rest_cookie_invalid_nonce`) are still to be verified. Query (T15): `src/Query/Criteria.php` validates and normalises every read request (mode, search, filters, orderby, order, page, per_page 1–100) against the field registry and throws before SQL is built; `src/Query/ProductQuery.php` is the only builder of catalogue read SQL — one prepared page statement plus a `COUNT(*)` over the identical FROM and WHERE, tables only from `ProductQuery::TABLES` as `%i` identifiers, every value a prepare argument, taxonomy filters as EXISTS sub-queries only when present, and a `LIMIT` on every statement. Route arguments and schemas (T14): never write a read route's `args` or item schema by hand — take them from `Rest\RouteSchema` (`paging_args()`, `fields_arg()`, `query_args()`, `filter_args()`, `item_schema( $title, $extra )`) and implement `Rest\ReadController::get_item_schema()`, registering it as the route's `schema`; filter arguments are `{ operator, value }` objects named after the field, and `criteria_input()` turns validated parameters into `Criteria` input. A new filterable field also needs its SQL in `Criteria::FILTERS` and `ProductQuery` before its argument accepts anything. `GET /bcm/v1/products` is registered with truthful pagination and empty `items`, which T18 fills.
