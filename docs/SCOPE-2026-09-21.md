# Bulk Catalogue Manager for WooCommerce — agreed scope

Grilled with Wade, 21 September 2026 (four rounds). Research behind it: README.md, market-scan.md,
native-building-blocks.md, site-facts.md in this folder.

## What it is
A standalone, free (GPLv3, "free as in freedom"), WordPress.org-listed plugin that gives a
WooCommerce store owner a simple, beautiful screen to manage many products at once. It works on
a bare WooCommerce site and edits native WooCommerce product data only. No dependency on, module
for, or reference to any other plugin. Nothing client-specific.

## Non-goals
- Per-customer or per-group product access: not a WooCommerce concept; belongs to B2B plugins.
- Any Acme-specific field or filter.
- Imports: WooCommerce's native importer stays the import path.
- Paid tiers: none.

## Placement and access
- wp-admin page under Products, named Bulk Catalogue Manager.
- Default capability: manage_woocommerce (administrators and shop managers); setting to restrict
  to administrators.

## Version 1
**Grid.** WordPress DataViews, server-side paged, styled as WordPress 7 admin. Product rows with a
category tree panel beside them. Select all matching a filter, not just the page.

**Fields (single-value native fields).** Status, catalogue visibility, featured, categories, tags,
regular price, sale price, stock status, stock quantity, manage stock, SKU, weight, dimensions,
shipping class, tax status, tax class, sold individually, reviews on/off.

**"Visible on site" switch.** One simple toggle per row mapping to catalogue visibility
hidden/visible; the full four-way field and status remain in the detail panel and bulk actions.

**Variations.** First-class. Parent rows expand to show editable variation rows, and a flat
variations mode lists variations with their parent. Every bulk action has an "apply to
variations" option, default on for status and visibility, off for price and stock.

**Bulk edit kinds.** Set value; increase/decrease price by amount or percent; round; copy regular
to sale; find and replace in text fields; add or remove categories and tags without replacing the
rest. Sale schedule in version 2.

**Category tree.** Browse, filter, assign; create, rename, drag to re-parent, reorder.

**Saved views and export.** Saved filters and column layouts per user; CSV export of the current
view.

**Preview, history, undo.** Preview before apply. Every batch journaled with before-state; any
batch reversible from a history screen; full audit log of every change. Retained 90 days by
default, adjustable.

**Engine.** Custom REST routes (cookie + nonce), WooCommerce CRUD writes queued through Action
Scheduler in batches, lean read queries for the grid. Built to WordPress.org standards from day
one: coding standards, translation-ready, no external calls, uninstall cleanup.

## Version 2
Images, descriptions, attributes, up-sells/cross-sells, purchase note, menu order; sale schedule.
Generic custom fields: any post meta registered with register_post_meta as a typed column, plus
an ACF / Secure Custom Fields bridge exposing product field groups through ACF's public API.

## Process
1. Clickable HTML prototype of four screens (grid with tree, variations expanded, bulk action
   panel, history and undo), WordPress-admin styled. Wade signs off, then the client sees it.
2. Build version 1 in repo `bulk-catalogue-manager-for-woocommerce` under Wade's GitHub, in
   Software/WordPress like PunchOut and Hide Prices; British spelling throughout.
3. Build live on example.com (Wade: non-blocking). Every write reversible from day one.
4. Google Sheet stays for the client until the plugin is proven, then retires. Export replaces it.
5. List on WordPress.org.
